# Locations and Time (W1)

World authoring is available in Creator's **Locations and time** workspace and through the same `read_world`, `review_world`, and `apply_world` MCP operations. No generation is involved. Review returns previous/proposed definitions and an exact fingerprint; Apply requires separate approval and an operation UUID. Identical retries replay the saved outcome, including after restart/full-fidelity restore. Concurrent changes require a fresh review, never overwrite. Applying does not compile or publish.

## Definition

`cyoa.world-definition` version 1 is an immutable `world-definition` artifact. It supports up to 60 hierarchical locations, 100 directed connections, 100 local actions and six distinct wait durations, bounded to 48,000 UTF-8 bytes so complete Unicode reads and before/after reviews fit MCP. Location IDs, connection IDs and action IDs are unique within their collections. Cycles, missing endpoints and ambiguous passage/location bindings are rejected. Grouping areas need no passage; playable locations bind exact passage-plan versions. The starting location must bind the game's start passage. Revised passages require explicit rebinding and re-review. Removed locations/connections are reviewed as a complete new definition, not silently repaired.

Map artwork pins exact approved V1 image versions. Markers are percentages of the map frame and are rendered as accessible controls, not baked into artwork. The parent's map shows its immediate children; area selection and a text location list remain available without images. Maps are inspection surfaces, not walking/pathfinding engines. Approved image replacements do not change existing world references or historical builds. Asset usage includes current map assignments.

Connections have an explicit direction and 0–1,440 integer travel minutes. Reverse travel needs its own connection. Local actions have a label, 0–1,440 minute cost and authored result text; they do not create events, inventory or generated narration. Daily location hours are optional: inclusive opening, exclusive closing, with overnight intervals supported. Parent hours also constrain arrival. Null means always open; equal endpoints are rejected as ambiguous. Travel checks the destination at **arrival**, not departure. A player already inside may wait or leave after closing; closing never traps a save.

## Runtime and Compatibility

The existing native compiler captures exact world content and map references alongside passages/prose. A nested `cyoa.native-world` version 1 projects public definitions and approved PNGs only. Its payload participates in the native bundle fingerprint; source provenance, private filenames, requests and receipts are excluded. Historical inputs resolve their own versions. Text builds and existing v1 save fixtures retain their original shapes/fingerprints. No SQLite migration is needed.

World saves add a versioned `state.world` containing location ID and integer elapsed game minutes. Day 1 starts at minute 0; display is derived without wall-clock or timezone dependence. The upper bound is 52,560,000 minutes. Only confirmed travel, local actions and authored waiting advance this clock. Map inspection, menus, reading, cancelled confirmations and rejected actions do not. Existing story choices retain their existing effects and zero implicit time cost; entering a passage assigned to a location updates location identity. Unassigned narrative passages retain the last location. Travel is an explicit authored alternative to story choices, not an inferred passage-graph edge. Chapters, event prerequisites, schedules and inventory are not W1 features.

World actions use the existing runtime's passage entry and state cloning, turn/visit accounting, player session validation, autosaves, manual slots, rewind and restart. Every committed action advances one turn (even a zero-minute action); waiting/local actions do not fabricate passage visits. Versioned world state retains stationary-turn accounting for save validation. Input state remains unchanged on rejection. Time overflow, unsupported wait durations, missing connections and actions from another location are rejected before commit. Save validation rejects unknown locations, mismatched mapped passages, unsupported world state versions and missing/injected world state. Saves remain bound to their exact bundle. An autosave write failure retains the existing explicit recovery controls.

Standalone HTML and static ZIP package map assets and work with Creator offline. Markdown and Twee explicitly reject enabled worlds rather than dropping travel/time mechanics. Full/privacy archives, backup/restore and duplication retain exact world history. To disable a world, review and apply a disabled definition with cleared locations/connections/actions; prior builds remain available. Missing/stale dependencies block new compilation with a diagnostic; restoring them or reviewing a corrected/disabled definition recovers without deleting history.

## Verification

`packages/runtime/test/world.test.ts` exercises midnight, overnight/parent hours, arrival boundaries, integer limits, atomic rejection, normal choice compatibility, save integrity, rewind/restart and malformed worlds. `apps/server/test/world.test.ts` covers exact review, concurrency, retries, rollback, direct persistence, historical builds, lineage, portability/duplication and byte limits. `apps/web/test/world.test.tsx` checks consent, review invalidation, lost responses, unmount and map fallback. `e2e/world.spec.ts` authors through MCP and Creator, tests stale concurrent review/lost Apply, then shuts Creator down and plays home/cafe/station through standalone and nested static exports on desktop/mobile, with cancellation, midnight, save/reload/load, local actions, waiting and closed arrivals.

The checkpoint also requires the full lint/typecheck/unit/build/browser suites and an installed native MCP-client check. Passing these does not claim exhaustive progression analysis or elimination of unrelated historical browser flakes.
