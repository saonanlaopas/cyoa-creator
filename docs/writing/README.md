# Fiction Craft integration

`FICTION_CRAFT.md` is the single editable guide. Version **0.1** is the supplied 8,248-byte UTF-8 edition, SHA-256 `c42b4cd0239c26d1541615dd62ddc115281311d1f838e980468ca65631323e96`. `fiction-craft-versions.json` records released identities. `node scripts/bundle-fiction-craft.mjs` derives the runtime copy; build/lint use `--check` and fail if source, edition, hash or generated bytes disagree. A release must keep previous edition digests and use a new edition for changed bytes. Project snapshots are immutable provenance, not editable copies.

New Quick, Long-form, setup, adaptation and MCP fiction projects record **enabled** and the current snapshot in their creation transaction. Missing settings in an existing/imported/restored project resolve to **disabled / legacy-preserved** with no write on read. No population-wide opt-in occurs. Duplicates/imports retain their source setting and selected snapshot; a legacy duplicate remains off. Corrupt or unsupported snapshots fail validation. Disabling retains the selected edition for re-enabling; installing a newer catalog does not silently upgrade a project.

Creator exposes **Fiction Craft preferences** in Quick and under **Authoring preferences** in Long-form. Review the preference change, then apply that exact review or cancel. The control preserves editable persistent commands, approved Creative Direction and scoped overrides. Those remain in their existing fields; the guide is never split into custom guidance. Preference changes do not change prose, locks or approvals. A pending authoring request whose settings or effective commands changed must be refreshed; completed output retains its historical snapshot.

Every new writing/planning context captures the settings version, enabled state, selected guide identity, full applied guide only when enabled, and effective command IDs/order/exact text/content digests. Existing scoped contexts carry exact project canon, task and applicable approved Creative Direction separately. Mutable command timestamps are not invented immutable versions. Source evidence stays quoted data. Provider messages receive one complete enabled guide, with identity metadata in quoted context; disabled requests receive no guide text. Full message bounds are checked before provider calls, including repair requests. Long-form previews account for instruction overhead without raising backend limits. Draft/plan preview envelopes conservatively reserve the maximum durable ID sizes before their job IDs exist.

MCP exposes `read_authoring_settings`, `review_authoring_settings`, `apply_authoring_settings` and `read_authoring_context`; use the [current desktop allowlist](../examples/codex-local-mcp.toml). Settings operations use the same service as Creator, require exact-base review/explicit consent, and preserve identical-operation retries after restart. `read_authoring_context` supports bounded `draft`, `planning`, `world` and `scene` scopes. Scene scope requires `passageId`; see the [illustrated authoring workflow](../illustrated-scenes.md#upload-to-offline-export). Planning edits also carry their context in `prepare_edit`.

New external `submit_draft` requests use **contextVersion: 2** and the exact `authoringContextFingerprint` returned by a draft-context read with the same exact author request. Settings, commands, graph or required context changes require a fresh read. The draft and immutable instruction binding commit with the ordinary candidate/receipt transaction. It remains external/manual-input prose with connected-assistant provenance: no claim of an internal model call or inferred approval. Completed legacy receipts replay before new-input requirements; new unbound legacy mutations are rejected. Candidate creation, prose acceptance, foundation approval, artwork approval and compilation remain separate actions.

Native desktop Codex tool discovery is a **separate pending gate**. Cloud mocked HTTP and installed MCP SDK tests cannot satisfy it. After updating the local allowlist and restarting Codex/Creator, run the [desktop smoke test](../connected-editing.md) and additionally ask Codex to read the project settings, prepare a preference review, cancel it, and read a narrow authoring context. Confirm no setting or creative content changed. Apply a setting only if you explicitly approve the displayed batch.

## Format-only repair boundary

The application compares repaired JSON with an independently recovered original baseline, including every decoded prose string, whitespace/newline, negation, ID, choice, cost, condition and effect. Object-key order and equivalent JSON string escapes may differ; array order and decoded values may not. Schema-valid rewriting is rejected before any candidate/proposal success is persisted. Protection is the same with the guide on or off.

Recovery accepts complete fenced JSON, explicit trailing commas and missing final container closers after complete values. It rejects duplicate keys, truncated strings, missing values, ambiguous/missing substantive content, extra garbage and excessive bounds/depth. It never infers missing prose or authorizes craft revision. A schema-invalid or irrecoverable original requires a separately authorized fresh revision, rather than an automatic substantive “repair.” Graph repair explicitly requested by Quick remains a distinct operation, not format-only repair.

A3 source analysis and A4 intent extraction receive no craft-writing instructions; their structural repairs still receive the same content-preservation check. Manual edits, deterministic transforms, restores and exported runtime play do not gain model calls. Offline players retain canonical mechanics and contain neither guide instructions nor authoring settings.

This product integration does not implement or accept story content. The Sea Keeps His Name manuscript/artwork and its opening remain outside this change. Neutral fixtures verify delivery and enforcement; they do not establish literary quality, a complete comparative story playthrough, or independent acceptance.
